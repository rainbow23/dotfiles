# FileSearch / GrepSearch 検索履歴機能 計画書

## 目的

`[fzf]f`（FileSearch）・`[fzf]s`（GrepSearch）で入力したクエリを履歴として保存し、
picker 内から過去のクエリを呼び出して再検索できるようにする。

- 同じ文字列を何度も打ち直す手間をなくす
- nvim を再起動しても履歴が残る（永続化）
- 既存のキーマップ・挙動（Dir切替 / Pinned / キャッシュ保存 など）を壊さない

## 対象範囲

| 対象 | 含む | 備考 |
|------|------|------|
| FileSearch（`[fzf]f`） | ○ | `make_file_search` |
| GrepSearch（`[fzf]s`） | ○ | `make_grep_search` |
| BufGrepSearch | ○ | `make_grep_search` を共有するため Grep 履歴に相乗り |
| Old Files / Buffers / BLines / GrepCache | × | 今回は対象外 |
| plain vim（`vimrc.d/fzf.vim` の fzf.vim 版） | × | nvim（telescope 版）のみ |

## 仕様

### 1. 履歴の記録

- **記録タイミング**: picker が閉じられるとき、プロンプトが空でなければ記録する
  - `<CR>` / `<C-t>` / `<C-v>` / `<C-h>` で開いた場合
  - `<Esc>` で閉じた場合も記録する（「見つからなかったので後で言い直したい」ケースに対応）
  - 1 文字だけのクエリは記録しない（ノイズ防止。最小長は設定値で変更可）
- **重複**: 同じモードで同一クエリが既にあれば、古い方を消して先頭に移動する
- **上限**: プロジェクト × モードごとに最新 100 件。超えた分は古いものから削除
- **モード分離**: File 履歴と Grep 履歴は別々に保持する（ファイル名と grep パターンは性質が違うため）
- **プロジェクト分離**: 履歴は git root ごとに完全に分けて保持する。別プロジェクトの履歴は表示しない
  - プロジェクトの判定キーは **git root**（`git rev-parse --show-toplevel`）
  - git 管理外のディレクトリでは、起動時の `cwd` をキーにする
  - `<C-s>`（Dir切替）で検索ディレクトリを変えても git root は同じなので、同じ履歴を使う
  - BufGrepSearch も起動時の git root（なければ cwd）の Grep 履歴を使う

### 2. 履歴の呼び出し（picker 内）

シェルの履歴と同じ感覚でプロンプトを置き換える。

| キー | 動作 |
|------|------|
| `<C-k>` | 1 つ古い履歴をプロンプトに挿入 |
| `<C-j>` | 1 つ新しい履歴をプロンプトに挿入。最新を越えたら入力途中の文字列に戻す |
| `<C-e>` | 履歴一覧 picker を開く（後述） |

- 最初に `<C-k>` を押した時点のプロンプト文字列を「下書き」として退避し、`<C-j>` で戻ってきたら復元する
- 呼び出せるのは **現在のプロジェクト（git root）の履歴のみ**。新しい順に並べる
- プロンプト置換は `picker:set_prompt(text)` を使う。GrepSearch はそのまま live grep が再実行される

> キー選定理由: `<C-n>`/`<C-p>` は telescope の候補移動、`<C-r>` は FileSearch の MRU、
> `<C-s>`/`<C-o>`/`<C-c>`/`<C-f>`/`<C-l>`/`<C-t>`/`<C-v>`/`<C-h>`/`<Tab>` は既存で使用中。
> `<C-Up>`/`<C-Down>`（telescope 標準の履歴キー）は HHKB では押しにくいため採用しない。

### 3. 履歴一覧 picker

picker 内の `<C-e>`、または通常モードの `[fzf]r`（`:SearchHistory`）で開く。

```
SearchHistory [Grep]  Project:dotfiles  <CR>=再検索 <C-d>=削除 <C-e>=File/Grep切替
──────────────────────────────────────────────
 2026-10-19 14:02  make_grep_search
 2026-10-19 13:55  grep_cache
 2026-10-18 22:10  TODO\(
```

| キー | 動作 |
|------|------|
| `<CR>` | そのクエリを `default_text` にして元の検索（File/Grep）を開き直す |
| `<C-d>` | カーソル行の履歴を削除（`<Tab>` 複数選択時はまとめて削除） |
| `<C-e>` | File 履歴 ↔ Grep 履歴の表示切替 |

- 表示するのは現在のプロジェクトの履歴のみ。プロジェクト名（git root の末尾ディレクトリ）は prompt_title に出す
- 表示列: 最終使用日時 / クエリ
- picker 内の `<C-e>` から開いた場合は、呼び出し元の `opts`（cwd・git_root・file_dir など）を引き継いで戻る
  （`open_oldfiles_with_back` と同じ「戻れる遷移」パターン）

### 4. 保存形式

保存先は既存の GrepCache（`~/.vim/grep_cache`）に合わせて `~/.vim/search_history/` とする。
プロジェクトごとに 1 ファイルにして、File / Grep 両方の履歴をその中に持つ。

```
~/.vim/search_history/
├── %Users%rainbow%dotfiles.json
└── %Users%rainbow%work%myapp.json
```

- ファイル名は git root（git 管理外なら cwd）の絶対パスの `/`（Windows は `\` と `:` も）を `%` に置き換えたもの
  （vim の `undodir` と同じ方式。パスが違えば必ず別ファイルになり、ファイル名から元のパスも読める）
- パスは `fnamemodify(':p')` で正規化し、末尾の `/` を除いてからキーにする
  （GitBash の `/c/Users/...` と `C:/Users/...` の違いは `search.lua` の既存処理と同じ方法で揃える）

```json
{
  "version": 1,
  "root": "/Users/rainbow/dotfiles",
  "file": [
    { "query": "search.lua", "used_at": 1760850300, "count": 5 }
  ],
  "grep": [
    { "query": "make_grep_search", "used_at": 1760850120, "count": 3 }
  ]
}
```

- `count` は将来の「よく使う順」ソート用に保持しておく（初版では表示のみ・ソートには未使用）
- 書き込みは picker を閉じるたびに行う（件数が少なくコストは無視できる）
- JSON が壊れていた場合は `pcall` で握りつぶして空履歴として扱い、上書き保存で自己修復する

## 実装計画

### 変更ファイル

| ファイル | 変更内容 |
|----------|----------|
| `nvim/lua/rc/search_history.lua`（新規） | 履歴の読み書き・追加・削除・並べ替え、履歴一覧 picker |
| `nvim/lua/rc/search.lua` | FileSearch / GrepSearch の `attach_mappings` に記録・呼び出しを追加、`:SearchHistory` 定義 |
| `vimrc.d/search-keymaps.vim` | `nnoremap [fzf]r :<C-u>SearchHistory<CR>` を追加 |
| `docs/nvim-filesearch-grepsearch-refactor.md` | キーバインド表に `<C-k>`/`<C-j>`/`<C-e>` を追記 |
| `docs/folder-structure.md` | `search_history.lua` と `[fzf]r` を追記 |

### `rc/search_history.lua` の API 案

```lua
local M = {}
M.project_key(git_root, cwd)       -- 履歴ファイルのパスを返す（git_root がなければ cwd）
M.load(mode, root)                -- mode: 'file' | 'grep' → そのプロジェクトの entries（新しい順）
M.add(mode, query, root)          -- 重複除去・先頭移動・上限カット・保存
M.remove(mode, queries, root)     -- 複数削除
M.attach(prompt_bufnr, map, mode, opts)
                                  -- <C-k>/<C-j>/<C-e> の登録と、close 時の記録フック
M.open_picker(mode, back_opts)    -- 履歴一覧 picker
return M
```

`M.attach` を各 picker の `extra_mappings` 内で 1 行呼ぶだけにして、`search.lua` 側の変更を最小にする。

```lua
attach_mappings = make_attach_mappings(true, function(prompt_bufnr, map)
  history.attach(prompt_bufnr, map, 'grep', opts)
  -- 既存のマッピング …
end),
```

### 記録フックの実装方針

picker を閉じる経路は複数ある（`select_entry` の自前 close、`util.open_multi_or`、`<Esc>`、`<C-s>` の開き直し、
`<C-r>`/`<C-b>` の遷移）。個別に記録処理を足すと漏れるため、**閉じる処理 1 か所でフック**する。

1. 第一案: `attach_mappings` 内で `actions.close:enhance({ pre = record })`
   - telescope の action 置換は picker 単位でクリアされる想定だが、**グローバルに残らないか要検証**
2. 代替案: prompt バッファに `BufLeave`（`once = true`, `buffer = prompt_bufnr`）の autocmd を張り、
   `action_state.get_current_picker(prompt_bufnr):_get_prompt()` で文字列を取得して記録

`<C-s>`（Dir切替）・`<C-r>`/`<C-b>`（MRU/Buffers 遷移）でも閉じるたびに記録されるが、
重複除去で先頭移動になるだけなので問題ない。

### 履歴カーソル（`<C-k>`/`<C-j>`）の状態管理

```lua
local idx, draft = 0, nil       -- picker ごとのローカル状態（attach 内のクロージャに保持）
-- <C-k>: idx == 0 なら draft = 現在のプロンプト。idx = min(idx + 1, #list) → set_prompt(list[idx])
-- <C-j>: idx = max(idx - 1, 0) → idx == 0 なら set_prompt(draft) else set_prompt(list[idx])
```

- 一覧は `attach` 時点で `M.load(mode, root)` を 1 回だけ取得してキャッシュ
- GrepSearch で `<Tab>` による Pinned 状態（静的リスト）のときは、`set_prompt` しても live grep に戻らないため
  **`<C-k>`/`<C-j>` を無効化して通知を出す**（Pinned 中はフィルタ入力として扱われるため）

### ショートカット表示の更新

`file_search_shortcut` / `grep_search_shortcut` に `<C-k>/<C-j>=履歴 <C-e>=履歴一覧` を追加する。
タイトルが長くなりすぎる場合は `results_title` 側（`util.shortcut_common`）ではなく prompt_title に寄せる。

## 決定事項

| 項目 | 決定 |
|------|------|
| `<Esc>` で閉じた時も記録するか | 記録する |
| 履歴をプロジェクト別に分けるか | git root ごとに完全に分ける（git 管理外は cwd ごと） |
